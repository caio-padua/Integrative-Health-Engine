## 2. Bug confirmado — coluna `SEM` na página 2

### 2.1. Evidência (PDF do paciente FABIO MORGON, protocolo 2)

**Página 1** — substâncias COENZIMA Q10, PQQ 20MG, VITAMINA D3 600K, VITAMINA B12 2500MG, TIRZEPATIDA 2,5MG. Numeração da coluna `SEM` correta: **1 a 16**, datas 13/06/26 → 23/01/27.

**Página 2** — substância TESTOSTERONA BIO 25MG (8 sessões, 15/15 dias, início 13/06/26).

Esperado: numeração começando em 1 (ou no número da semana correta do protocolo).
Observado:

```
SEM 21 → 13/06/26 → 1/8
SEM 22 → 28/06/26 → 2/8
SEM 23 → 13/07/26 → 3/8
SEM 24 → 28/07/26 → 4/8
SEM 25 → 12/08/26 → 5/8
SEM 26 → 27/08/26 → 6/8
SEM 27 → 11/09/26 → 7/8
SEM 28 → 26/09/26 → 8/8
```

**As datas estão corretas. A numeração da coluna `SEM` está errada.** O renderizador da página 2 está continuando o contador da página 1 (que reservou 20 linhas, mesmo com só 16 ocupadas), em vez de calcular o número da semana baseado na data da sessão.

### 2.2. Causa-raiz provável

A função que renderiza a página 2 está usando um contador acumulado (algo como `weekIndex = previousPageLastWeek + 1`) em vez de derivar o número da semana da própria data da sessão (algo como `weekNumber = Math.floor((sessionDate - protocolStartDate) / 7) + 1`).

### 2.3. Comportamento esperado — preciso da sua decisão de produto

Há **duas leituras válidas** da coluna `SEM`. Preciso definir qual você implementou e qual queremos:

| Opção | Definição | Como ficaria a página 2 |
|---|---|---|
| **A** | `SEM` = número sequencial da **ida do paciente à clínica** | TESTOSTERONA SEM 1 = 13/06 (mesma ida da pág 1), SEM 2 = 28/06 (ida nova), SEM 3 = 13/07 (mesma ida da pág 1 SEM 3), etc. **A confluência semanal cruza páginas.** |
| **B** | `SEM` = número da semana **do protocolo a partir da data de início da substância** | TESTOSTERONA SEM 1 = 13/06, SEM 3 = 28/06 (15 dias = 2 semanas depois), SEM 5 = 13/07, etc. **Cada substância tem sua própria contagem.** |
| **C (atual, errado)** | Contador acumulado das linhas reservadas | 21, 22, 23… |

**Minha posição:** prefiro **A** — `SEM` representa **ida à clínica**, e a confluência semanal (Regra Ouro: uma única ida agrupando todas as substâncias daquela semana) deve **cruzar páginas**. Assim a equipe de enfermagem cruza-referência entre as páginas pelo número da semana. Se você implementou **B** ou tem outra leitura, me diga **antes** de corrigir.

## 3. Especificação do RAS — versão de referência

Reapresento aqui para que **fonte única da verdade** fique sem ambiguidade. Se algo diverge da sua implementação atual, sinaliza.

### 3.1. Layout da página (grid)

- **Grid:** 34 colunas × 44 linhas por página.
- **Cabeçalho fixo** (linhas 1–8): identificação do paciente, médico, unidade, protocolo, valor do tratamento, datas.
- **Linha de substâncias** (linhas 9–11): até **5 substâncias por página**. Cada substância exibe: NOME · APLICAÇÕES (totais) · FREQUÊNCIA (X/X DIAS) · INÍCIO DA APLICAÇÃO (DD/MM/AA).
- **Tabela de sessões** (linhas 12–40, 20 linhas úteis por página): colunas `SEM` · `DATA AGEND.` · `HORA` · `CIÊNCIA/RUBRICA PACIENTE` · `RUBRICA ENF.` · `DATA EFETIVA` · `OBS` · uma coluna por substância (até 5).
- **Rodapé** (linhas 41–44): assinatura paciente, médico responsável (com carimbo), enfermagem responsável (com carimbo), `PÁG. X / Y`.
- **Paginação:** se houver mais de 5 substâncias, abre nova página com mesmo cabeçalho/rodapé e novas substâncias.

### 3.2. Variantes

- **SIMPLES:** preto e branco, sem temas.
- **PREMIUM:** tema navy (#1B2A4A) + dourado (#D4AF37) + faixas zebra.
- **JURÍDICO:** documento de consentimento (LGPD), gerado em fluxo separado mas com a mesma identificação do paciente.

### 3.3. Regra Ouro — confluência semanal

> **Definição:** numa mesma semana ISO (segunda a domingo), o paciente vai **uma única vez** à clínica. Todas as substâncias que cairiam em datas diferentes daquela semana são consolidadas no **primeiro dia previsto** dessa semana.

Algoritmo de referência (pseudocódigo):

```typescript
type Substance = {
  name: string;
  totalSessions: number;
  frequencyDays: number;   // ex.: 15 ou 30
  startDate: Date;          // data de início desta substância
};

type ProtocolSession = {
  date: Date;
  substances: Array<{ name: string; sessionIndex: number; total: number }>;
};

function generateAgenda(substances: Substance[]): ProtocolSession[] {
  // 1) Gera todas as datas brutas por substância
  const raw: Array<{ date: Date; sub: Substance; sessionIndex: number }> = [];
  for (const sub of substances) {
    for (let i = 0; i < sub.totalSessions; i++) {
      const d = addDays(sub.startDate, i * sub.frequencyDays);
      raw.push({ date: d, sub, sessionIndex: i + 1 });
    }
  }

  // 2) Agrupa por semana ISO (segunda como dia 1)
  const byWeek = groupBy(raw, item => isoWeekKey(item.date));

  // 3) Para cada semana, elege a PRIMEIRA data e consolida
  const result: ProtocolSession[] = [];
  for (const [weekKey, items] of byWeek) {
    const earliest = items.reduce((a, b) => a.date < b.date ? a : b).date;
    result.push({
      date: earliest,
      substances: items.map(it => ({
        name: it.sub.name,
        sessionIndex: it.sessionIndex,
        total: it.sub.totalSessions,
      })),
    });
  }
  return result.sort((a, b) => a.date.getTime() - b.date.getTime());
}
```

### 3.4. Data de início **por substância**

Importante: cada substância tem **sua própria data de início** (campo opcional). Comportamento:
- **Vazio** → usa a data de início do **protocolo** (campo principal).
- **Preenchido** → começa naquela data específica (caso de uso: intercalar VIT B12 começando 1 semana depois para distribuir as idas semanais).
